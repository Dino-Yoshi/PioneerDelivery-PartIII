## Defects and caveats

1. **Kiro engine is v2, not v3.** The run reported `"engine":"v2"`. `16` recommends a V3 harness. It worked with headless mode, but its behavior may differ from the docs. Re-check before the first real worker run.
2. **Model id echo.** The CLI accepted `--model claude-haiku-5.5`, but the stream output does not print the model id, so the model actually used is inferred from the accepted flag and the 0.0019-credit cost, not proven.
3. **Toolchain mismatch.** The container has GCC 14.2 and CMake 3.31.6; the host has GCC 16.2.1 and CMake 4.4.5. The project must configure and build on both. Decision needed on which toolchain is canonical for G4 and for the release binary (proposal below).
4. **Unpinned base.** The base image is pulled by tag from a mirror; the digest is recorded above but not enforced.
5. **Probe limits.** The git-metadata test shows the worker cannot reach the common dir because only the worktree directory is mounted. Writing to Git metadata is therefore impossible by construction rather than denied by a permission error. The 4-worker parallel memory load was not run.
6. **Docker not used.** Rootless Podman was the only runtime tested.

## Decision

G0 is PASS on the executed evidence above. Implementation does not start until the owner explicitly authorizes execution. Open item for the owner: caveat 3.
