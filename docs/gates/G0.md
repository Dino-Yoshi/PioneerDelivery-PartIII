## Defects and caveats

1. **Kiro engine.** The default headless engine is v2. v3 is selected with `--agent-engine v3` and was verified (see table); workers will use v3. **Stale session lease:** v3 does not release its lease on exit, so `agentctl` (OPS-01) must, under the orchestrator's per-worker lock and only when no container for that worker is running, move aside the stale lease before each resume. Use a fixed container hostname per worker as an extra guard.
2. **Model id echo.** The CLI accepted `--model claude-haiku-5.5`, but neither the v2 nor the v3 output prints the model id, so the model actually used is inferred from the accepted flag and the 0.0019-credit cost, not proven.
3. **Toolchain mismatch.** The container has GCC 14.2 and CMake 3.31.6; the host has GCC 16.2.1 and CMake 4.4.5. The project must configure and build on both. **Resolved by owner (2026-11-11):** the container toolchain (GCC 14, CMake 3.31) is canonical for worker builds, G4 and the release binary; a host build is an additional G4 check. `cmake_minimum_required` must not exceed 3.31.
4. **Unpinned base.** The base image is pulled by tag from a mirror; the digest is recorded above but not enforced.
5. **Probe limits.** The git-metadata test shows the worker cannot reach the common dir because only the worktree directory is mounted. Writing to Git metadata is therefore impossible by construction rather than denied by a permission error. The 4-worker parallel memory load was not run.
6. **Docker not used.** Rootless Podman was the only runtime tested.
